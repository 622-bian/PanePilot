# 验证指南

## 自动检查

运行 `scripts/Test.ps1`，预期输出 87 项检查 `PASS` 且退出码为 0。覆盖空屏优先、空白矩形搜索（含逐像素穷举对照）、无空白区域的分屏选择、单屏、负坐标、跨屏占用、显示器移除后的模拟快照、检测失败保守处理、窗口过滤和配置校验。

偏好检查覆盖最大化、最小化、关闭、手动还原、程序布局与旧窗口切换的状态区别，以及保存、重新读取、损坏文件和暂时写入失败的恢复。预加载恢复检查覆盖重试间隔、次数上限、未确认窗口阻止重试、手动暂停与显式恢复。检查输入使用临时文件和模拟状态，不读取个人配置或聊天内容。

这些是确定输入的规则测试，不代表真实显示器热插拔、Edge 页面或 Windows 焦点行为全部正确。GitHub Actions 的 Windows 构建和测试也不能代替交互桌面验收。

## 原生测试

运行 `scripts/Test.ps1 -Native` 后启动生成的 `dist/tests/NativeLayoutSmoke.exe`。它只创建、跨屏移动、最大化、恢复和关闭自身的临时窗口。结果中的每个显示器应出现 `PASS ... maximize + restore16x9`；宽度足够的显示器还应通过普通/最大化分屏撤销、过期目标跳过、最小宽度失败回退、关闭一方后撤销的检查。末尾应为 `PASS native layout`。

失败判据：没有可靠的显示器快照、目标屏幕不符、最大化状态不符或恢复后外框不是预期的 16:9 物理像素尺寸。

## GPT 实际验收

1. 留一块显示器只显示桌面，在另一屏操作并按 Ctrl+Alt+G。GPT 应在空屏最大化，已有窗口不移动。
2. 在默认的“保持最大化”模式下，两屏都有窗口时，GPT 应在当前操作屏最大化，已有窗口不移动。依次最小化和关闭刚交付的 GPT，再按快捷键，下一个窗口仍应最大化。
3. 让一个普通窗口跨越屏幕边界，两边都应计为占用。
4. 最小化副屏所有普通窗口后，该屏应重新成为空屏；桌面和任务栏不应阻止它。
5. 连续按两次，分别确认备用取用和普通新建都遵守所选模式。重启助手后检查模式仍保持原选择。
6. 单屏、不同 DPI、复制显示、拔插显示器、切换虚拟桌面应分别验收。仅看到几何单元测试通过，不代表这些真实系统状态都已测试。
7. 从托盘选择“自动布局”。两屏都有窗口，但有 720×405 空白矩形时，GPT 应先使用空白区域；没有空白区域时，前台普通窗口在左、GPT 在右。分屏后按 Ctrl+Alt+Shift+G 或使用托盘撤销，原窗口应恢复分屏前的状态，GPT 应保持打开。分别验证普通窗口和最大化窗口。
8. GPT 加载期间移动原窗口或切换到其他应用，不应调整旧的前台窗口。窗口关闭、最小尺寸过大和显示器布局变化应能保守处理。
9. 手动还原前台最大化 GPT，托盘应变为“自动布局”；再次最大化应变回“保持最大化”。最小化、恢复最小化窗口、关闭、切换到旧的小窗口、程序分屏和撤销不应改写模式。

可选分屏集成测试：先运行助手并等到备用就绪，运行 `scripts/Test.ps1 -Resident` 后启动 `dist/tests/ResidentSmoke.exe`。它临时选择自动布局，用自己的空白窗口盖住显示器；在 `PanePilot integration control` 中点击按钮或按回车，触发一次真实 GPT 取用和 IPC 撤销。测试结束恢复原模式，只关闭临时窗口，保留新 GPT。结果写入 `dist/tests/resident-smoke-result.txt`。`lastDelivered` 在所有权转移时写入，早于布局结束，因此测试还必须等待两个窗口的实际外框符合预期。

可选偏好集成测试：运行 `scripts/Test.ps1 -Preference` 后启动 `dist/tests/PreferenceSmoke.exe`，在自己的测试窗口中按回车开始。它创建真实的空白 GPT，验证“最大化→最小化→下一窗最大化”“最大化→关闭→下一窗最大化”，模拟还原/最大化操作并检查模式变化，再用独立 `--once` 进程验证持久化。结果写入 `dist/tests/preference-smoke-result.txt`，末尾应为 `PASS preference integration`。只操作本次测试创建的 GPT，不读取输入框或聊天内容；结束后留下最大化模式和测试产生的部分空白 GPT 窗口。

偏好测试必须等待 `preload-delivered` 完成记录后才操作交付窗口；仅看到 `IsZoomed` 为真不代表整个布局已经结束，否则测试自己的最小化动作可能与交付过程竞争。此测试使用真实 Win32 状态变更，但不等同于鼠标点击标题栏按钮或实际全局快捷键的端到端验收。

## 从日志定位

- `layout-request`：每次按键的显示器数、各屏占用数及 `scanMs`，不沿用上一次按键结果。
- `layout-delivery`：交付使用的布局。立即交付可以复用本次按键的快照；冷启动或快照超过 100 毫秒会重新检测。
- `layout-applied`：实际最大化状态、外框大小和 `success`。
- `layout-duration`：布局处理耗时；`preload-delivered requestMs` 是取用流程耗时，不是屏幕呈现时间或网络耗时。
- `layout-fallback`：目标布局未验证成功；最大化模式继续尝试在当前屏最大化，自动布局模式使用普通尺寸兜底。
- `window-mode`：模式变化和原因；`user-window-state` 来自前台 GPT 状态变化，`explicit-choice` 来自托盘或模式命令。
- `window-mode-save-error`：当前模式保留在内存，随后每隔至少 5 秒重试保存；保存成功前不保证跨重启保留。
- `split-applied`：两个半屏外框均验证成功，撤销记录已建立。
- `split-rollback`：分屏未完成，分别记录两边恢复结果。
- `split-undo`：分别记录两边的撤销结果；窗口已关闭时跳过，不操作复用的窗口句柄。
- `preload-fault`：候选 PWA 未能确认或准备失败，包含失败次数、未确认窗口数和是否停止重试。状态文件区分 `paused`（手动暂停）、`waiting-unresolved`、`retry-wait`、`fault-paused`。

保持最大化模式应有 `mode=remembered-maximize`；自动布局的空屏路径应有 `mode=empty-maximize`。两者均须验证 `maximized=True`、`success=True`。空白区域应有 `mode=free-space` 和预期尺寸。`mode=split-candidate` 只是策略选择，必须看到 `split-applied success=True` 才能说明分屏成功。最大化外框可能包含屏幕边缘外的不可见边框，不应仅根据外框超过工作区数像素判断失败。

不要直接上传完整配置或日志。报告前删去私人路径、窗口句柄、时间等不必要信息。

## 当前验证边界

本轮实际桌面验证（2026-11-06）：两块不同缩放显示器上的临时窗口最大化/还原、分屏、普通/最大化撤销、失败回退及关闭一方后的撤销通过。真实 GPT 的备用取用、最小化/关闭后的下一窗最大化、前台手动状态变化识别、独立冷启动读取最大化偏好、助手重启后保留偏好通过。真实 GPT 与临时前台窗口分屏、IPC 撤销通过；测试结束恢复最大化模式。两个快捷键均成功注册。

三次已就绪备用窗口的 `requestMs` 分别为 18、28、29 毫秒，桌面扫描为 0、1、0 毫秒；这是程序内部计时，不能据此承诺按键到屏幕呈现的延迟或 p95。独立普通新建约 3.3 秒，仍受 Edge 和页面加载影响。

尚未验证：全局键盘组合的实际按键、标题栏鼠标操作、物理拔屏、复制显示与虚拟桌面切换、冷启动后的分屏，以及故意制造真实 Edge 标记识别超时后的完整恢复流程。故障恢复目前由确定输入的规则测试支持，正常预加载路径另有真实桌面验证。

已知限制：此前自动布局模式在高缩放副屏的真实 `--once` 测试中，目标 720×405 被 Edge 限制成 772×405，触发 `layout-fallback`。自动布局的普通尺寸兜底仍只检查 SetWindowPos 返回值，不能保证严格 16:9；精确结果应看兜底之前的 `layout-applied`。本轮保持最大化模式不会因这类失败降级成小窗口，但没有修复自动布局的 Edge 最小尺寸限制。真实 GPT 的空屏目标选择目前由布局规则和原生临时窗口测试共同支持，尚未专门清空一块屏幕进行实际 GPT 验收。
