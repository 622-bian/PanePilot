# 验证指南

## 自动检查

运行 `scripts/Test.ps1`，预期输出 61 项检查 `PASS` 且退出码为 0。覆盖空屏优先、空白矩形搜索（含逐像素穷举对照）、无空白区域的分屏选择、单屏、负坐标、跨屏占用、显示器移除后的模拟快照、检测失败保守处理、窗口过滤和配置校验。

这些是确定输入的规则测试，不代表真实显示器热插拔、Edge 页面或 Windows 焦点行为全部正确。GitHub Actions 的 Windows 构建和测试也不能代替交互桌面验收。

## 原生测试

运行 `scripts/Test.ps1 -Native` 后启动生成的 `dist/tests/NativeLayoutSmoke.exe`。它只创建、跨屏移动、最大化、恢复和关闭自身的临时窗口。结果中的每个显示器应出现 `PASS ... maximize + restore16x9`；宽度足够的显示器还应通过普通/最大化分屏撤销、过期目标跳过、最小宽度失败回退、关闭一方后撤销的检查。末尾应为 `PASS native layout`。

失败判据：没有可靠的显示器快照、目标屏幕不符、最大化状态不符或恢复后外框不是预期的 16:9 物理像素尺寸。

## GPT 实际验收

1. 留一块显示器只显示桌面，在另一屏操作并按 Ctrl+Alt+G。GPT 应在空屏最大化，已有窗口不移动。
2. 两屏都有窗口，但有 720×405 空白矩形时，GPT 应先使用空白区域；没有空白区域时，前台普通窗口在左、GPT 在右。原窗口不满足分屏条件时才退回普通窗口。
3. 让一个普通窗口跨越屏幕边界，两边都应计为占用。
4. 最小化副屏所有普通窗口后，该屏应重新成为空屏；桌面和任务栏不应阻止它。
5. 连续按两次，分别确认备用取用和普通新建都遵守规则。
6. 单屏、不同 DPI、复制显示、拔插显示器、切换虚拟桌面应分别验收。仅看到几何单元测试通过，不代表这些真实系统状态都已测试。
7. 分屏后按 Ctrl+Alt+Shift+G 或使用托盘撤销，原窗口应恢复分屏前的状态，GPT 应保持打开。分别验证普通窗口和最大化窗口。
8. GPT 加载期间移动原窗口或切换到其他应用，不应调整旧的前台窗口。窗口关闭、最小尺寸过大和显示器布局变化应能保守处理。

可选完整集成测试：先运行助手并等到备用就绪，运行 `scripts/Test.ps1 -Resident` 后启动 `dist/tests/ResidentSmoke.exe`。它会用自己的临时空白窗口盖住显示器；在 `PanePilot integration control` 中点击按钮或按回车，触发一次真实 GPT 取用和 IPC 撤销。测试结束只关闭临时窗口，保留新 GPT。结果写入 `dist/tests/resident-smoke-result.txt`。`lastDelivered` 在所有权转移时写入，早于布局结束，因此测试还必须等待两个窗口的实际外框符合预期。

## 从日志定位

- `layout-request`：按键时的显示器数、空屏数及目标。
- `layout-delivery`：交付前重新检测的结果；不同可能是加载期间布局变了。
- `layout-applied`：实际最大化状态、外框大小和 `success`。
- `layout-fallback`：目标布局未验证成功，退回普通尺寸。
- `split-applied`：两个半屏外框均验证成功，撤销记录已建立。
- `split-rollback`：分屏未完成，分别记录两边恢复结果。
- `split-undo`：分别记录两边的撤销结果；窗口已关闭时跳过，不操作复用的窗口句柄。
- `preload-paused reason=window-marker-not-found`：候选 PWA 未能确认，暂停预加载而不继续积累窗口。

空屏路径应有 `mode=empty-maximize`、`maximized=True`、`success=True`；空白区域应有 `mode=free-space` 和预期尺寸。`mode=split-candidate` 只是策略选择，必须看到 `split-applied success=True` 才能说明分屏成功。最大化外框可能包含屏幕边缘外的不可见边框，不应仅根据外框超过工作区数像素判断失败。

不要直接上传完整配置或日志。报告前删去私人路径、窗口句柄、时间等不必要信息。

## 当前验证边界

公开版：61 项自动检查通过。两块不同缩放显示器上的临时窗口分屏、普通/最大化撤销、失败回退及关闭一方后的撤销通过。常驻公开版的真实 GPT 预加载取用、与临时前台窗口左右分屏、IPC 撤销已验证；两个快捷键均成功注册。全局键盘组合的实际按键验收、普通新建后的分屏、物理拔屏、复制显示与虚拟桌面切换仍需分别验证。

已知限制：在高缩放副屏的真实 `--once` 测试中，目标 720×405 被 Edge 限制成 772×405，触发 `layout-fallback`。兜底日志里的 `normal-window-sized success=True` 只说明原有 SetWindowPos 调用返回成功，不能证明最终几何尺寸符合目标。精确布局结果应看兜底之前的 `layout-applied`；此问题留待后续处理 Edge 最小窗口尺寸时修复。

其来源原型：在双屏不同缩放环境中验证了临时窗口最大化/恢复，以及真实 GPT 在无空屏时的备用取用和普通新建。真实 GPT 的空屏最大化、物理拔屏和复制显示切换尚未现场验证。不要把来源原型的测试等同于公开版所有行为已验证。
